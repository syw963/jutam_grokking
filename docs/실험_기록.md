# 실험 기록

모든 실험: n=50, m=5, test 20,000, 값 집합 단위 split(seed 0), 모델 m0(2층, d=128), weight decay 1.0, full batch.
GPU: RunPod RTX 4090. 결과 폴더는 GPU 서버 기준.

## E1. 파일럿 (`/workspace/jutam_grokking/runs_pilot`, lr 1e-3, 옛 코드)

- train 0.1%(2,119개), 0.3%, 1% × 규칙 8개
- 결과: 정렬·첫 칸·순환 이웃·무작위 배선·대조군은 0.1%에서도 t_fit = t_gen (지연 0). 정렬 후 이웃합만 지연 2,700.
- 결론: train이 너무 크다. 0.1%에서도 순서쌍 2,450개를 거의 다 본다.

## E2. 작은 train (`runs_p2`, lr 1e-3, 옛 코드)

- train 64~1,024개 × 규칙 8개, seed 0
- 결과: 64~512개는 모든 규칙이 100 step에 외우고 test ≈ 0. 정렬만 일부 맞히고 정체(128개 0.44, 256개 0.67, 512개 0.86).
- 결론: 작으면 "외우기만" 또는 "부분 일반화 후 정체". 경계는 512~2,048 사이.

## E3. 큰 train (`runs_p3`, lr 1e-3, 옛 코드)

- train 2,048·4,096개 × 규칙 8개
- 결과: 국소 규칙은 바로 일반화. 그러나 **학습이 무너짐** (l1_first 2,048개 일반화 후 train 0.017, l1_sum train 1.0 → 0.0).
- 중단.

## E4. 안정성 테스트 (`/workspace/jutam_new/runs_stab`)

- l1_first, l1_sum × train 2,048 × {기본, fp32, grad clip 1.0, lr 3e-4}, 30,000 step
- 결과: 기본·fp32·clip은 모두 중간에 무너짐. **lr 3e-4만 안정.**
- 결론: lr 3e-4로 고정.

## E5. 일반화 경계 지도 (`runs_map`, lr 3e-4, 묶음 학습)

- train 256, 512, 768, 1,024, 1,536, 2,048, 4,096 × 규칙 8개 × seed 3 = 168 run, 최대 100,000 step
- 결과 (완료). 지연 = t_gen − t_fit:

| 규칙 | 768 | 1,024 | 2,048 | 4,096 |
|---|---|---|---|---|
| 순환 이웃 (Z₅) | **3/3**: 4,500 / 4,900 / 19,800 | 3/3: 500~1,000 | 3/3: 0 | 3/3: 0 |
| 무작위 배선 m0 (대칭 없음) | 1/3: 28,600 | 3/3: 3,200~4,400 | 3/3: 0 | 3/3: 0 |
| 첫 칸 (S₄) | 1/3: 21,400 | 3/3: 2,500 / 7,100 / 11,300 | 3/3: 100~300 | 3/3: 0~100 |
| 정렬 | 2/3: 35,900 / 61,600 | 3/3: 5,700 / 10,200 / 19,300 | 3/3: 0~800 | 3/3: 0 |
| 대조군 (+3, ×3, 정렬) | 1/3: 53,200 | 3/3: 11,100 / 13,300 / 18,600 | 3/3: 0~400 | 3/3: 0 |
| 정렬 후 이웃합 | 0/3 | 0/3 | 3/3: 12,200 / 19,600 / 65,300 | 3/3: 2,900~3,700 |
| 전체 합, 사슬 | 0/3 | 0/3 (10만 step) | 0/3 (10만 step) | 0/3 |

- 256·512개: 모든 규칙 일반화 0 (10만 step). 정렬·대조군은 0.7 / 0.85에서 정체.
- 1,536개: 국소 규칙·정렬·대조군 모두 지연 0~3,100. 정렬 후 이웃합 1/3(26,400). 전체 합·사슬 0/3.
- 경계에 가까울수록 지연이 커지고 seed 간 편차도 커진다(768개 순환 이웃 4,500~19,800).
- 768개에서 순환 이웃 3/3 일반화 vs 무작위 배선 1/3, 첫 칸 1/3. 순환 이웃과 무작위 배선은 coverage가 같다(아래).
- 연산 표 coverage (train에 나온 (자기 값, 참조값) 쌍 / 2,500): 768개에서 순환 이웃 79%, 무작위 배선 77%, 첫 칸 72%. 1,024개에서 86%, 86%, 82%.
- 결론: 경계 근처에서 grokking 확인. 경계 순서는 coverage와 맞지만, 순환 이웃 vs 무작위 배선은 coverage가 같은데도 차이 → 대칭 효과 후보.

## E6. 경계 정밀 측정 (`/workspace/jutam_b/runs_boundary`, 완료)

- `experiments/boundary.sh`. 규칙 13개 × train 768·896·1,024·1,152·1,280 × seed 5 = 325 run, 최대 40,000 step, lr 3e-4
- 규칙: 등변군 크기 5(`w5_next`, `w5_p0`, `w5_p2`), 6(`w6_p1`, `w6_p4`, `w6_p6`), 2(`w2_m4`, `w2_m12`, `w2_m15`), 1(`w1_m0`, `w1_m2`, `w1_m8`), 첫 칸(`l1_first`). 모두 T = a+b
- 첫 시도는 `CUDA_VISIBLE_DEVICES=1` 실수로 CPU에서 돌아 30분 낭비 → GPU 0에서 다시 실행. 묶음당 3.3GB.
- 검증: `w5_next`와 `w5_p0`(위치만 다른 같은 규칙)이 모든 크기에서 거의 같음 (768개 5/5·5/5, 지연 4,900 vs 7,000). 실험 정상.

결과 1. 등변군 크기로 묶으면 순서가 맞지 않는다 (일반화 run / 지연 중앙값):

등변군 6이 등변군 1보다 어렵다. 등변군 크기와 지연(log)의 상관은 −0.1 ~ −0.3으로 거의 없음.

결과 2. "참조 그래프"로 묶으면 깔끔하게 정렬된다. 출력 칸 i와 참조 칸을 잇는 간선을 그리면, a+b는 교환법칙이 있어서
한 예제가 주는 서로 다른 정보는 **서로 다른 무순서 쌍 수**(간선 수)다. 2-순환(i↔j)은 같은 쌍을 두 번 준다.

| 참조 그래프 (a+b) | 해당 배선 | 768 | 896 | 1,024 | 1,152 | 1,280 |
|---|---|---|---|---|---|---|
| 쌍 5 · 연결 (5-순환) | w5 ×3 | 15/15 · 4,900 | 15/15 · 2,500 | 15/15 · 400 | 15/15 · 200 | 15/15 · 100 |
| 쌍 4 · 연결 (나무) | w1 ×3, w2_m4 | 13/20 · 24,500 | 19/20 · 6,400 | 20/20 · 2,400 | 20/20 · 1,050 | 20/20 · 250 |
| 쌍 4 · 끊김 (삼각형+간선) | w6 ×3 | 1/15 · 10,700 | 12/15 · 9,300 | 15/15 · 4,400 | 15/15 · 2,300 | 15/15 · 700 |
| 쌍 3 · 끊김 | w2_m12, w2_m15 | 0/10 | 3/10 · 13,300 | 10/10 · 7,600 | 10/10 · 3,900 | 10/10 · 2,100 |

- 서로 다른 쌍 수와 지연(log)의 상관: −0.91 ~ −0.93 (1,024·1,152·1,280개). 일반화 비율과의 상관 0.78~0.81 (768·896개).
- 무순서 쌍 coverage와 일반화 비율의 상관 0.67~0.77, 순서쌍 coverage는 −0.1 (E5에서 쓴 순서쌍 coverage는 잘못된 척도였다).
- 같은 쌍 4개 안에서는 연결된 그래프(나무)가 끊긴 그래프(삼각형+간선)보다 쉬움.
- 첫 칸은 무순서 쌍 coverage가 높은데도 어렵다 (자기 자신 참조 x₁+x₁ = 2x₁ 칸이 따로 있음). 별도 설명 필요.
- 그래프: `analyze_boundary.py`의 `by_graph.png`, `by_symmetry.png`

## E7. 교환법칙 실험 (`runs_commute`, 준비 완료, 실행 전)

- `experiments/commute.sh`. E6의 배선 8개를 T(a,b) = a + 3b(교환법칙 없음)로 바꾼 규칙(`*_n3`) × train 768~1,280 × seed 5 = 200 run
- 목적: E6의 차이가 "대칭"이 아니라 "한 예제가 주는 서로 다른 정보 수" 때문인지 직접 검증.
  a+3b에서는 모든 배선이 서로 다른 순서쌍 5개를 준다. 등변군 크기는 그대로다.
  - 정보량 가설이 맞다면: 배선 간 차이가 사라지고 모두 5-순환과 비슷해진다.
  - 대칭 가설이 맞다면: 등변군 크기에 따른 차이가 남는다.
- E6와 같은 데이터·seed라 그대로 비교한다. `python analyze_boundary.py runs_boundary runs_commute`로 합쳐서 본다.
