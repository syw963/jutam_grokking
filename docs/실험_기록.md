# 실험 기록

모든 실험: n=50, m=5, test 20,000, 값 집합 단위 split(seed 0), 모델 m0(2층, d=128), weight decay 1.0, full batch.
GPU: RunPod RTX 4090. 결과 폴더는 GPU 서버 기준.

## E1. 파일럿 (`/workspace/jutam_grokking/runs_pilot`, lr 1e-3, 옛 코드)

- train 0.1%(2,119개), 0.3%, 1% × 규칙 8개
- 결과: 정렬·첫 칸·순환 이웃·무작위 배선·대조군은 0.1%에서도 t_fit = t_gen (지연 0). 정렬 후 이웃합만 지연 2,700.
- 결론: train이 너무 크다. 0.1%에서도 순서쌍 2,450개를 거의 다 본다.

## E2. 작은 train (`runs_p2`, lr 1e-3, 옛 코드)

- train 64~1,024개 × 규칙 8개, seed 0
- 결과: 64~512개는 모든 규칙이 100 step에 외우고 test ≈ 0. 정렬만 일부 맞히고 정체(128개 0.44, 256개 0.67, 512개 0.86).
- 결론: 작으면 "외우기만" 또는 "부분 일반화 후 정체". 경계는 512~2,048 사이.

## E3. 큰 train (`runs_p3`, lr 1e-3, 옛 코드)

- train 2,048·4,096개 × 규칙 8개
- 결과: 국소 규칙은 바로 일반화. 그러나 **학습이 무너짐** (l1_first 2,048개 일반화 후 train 0.017, l1_sum train 1.0 → 0.0).
- 중단.

## E4. 안정성 테스트 (`/workspace/jutam_new/runs_stab`)

- l1_first, l1_sum × train 2,048 × {기본, fp32, grad clip 1.0, lr 3e-4}, 30,000 step
- 결과: 기본·fp32·clip은 모두 중간에 무너짐. **lr 3e-4만 안정.**
- 결론: lr 3e-4로 고정.

## 칸당 관찰 수로 E6·E7을 한 곡선에 (`analyze_obs.py`)

- 칸당 평균 관찰 수 = train 개수 × 한 예제가 주는 서로 다른 쌍 수 / 연산 표 칸 수(a+b 1,275, a+3b 2,500)
- 이 값 하나로 a+b(쌍 3·4·5)와 a+3b가 한 곡선에 모인다. 완전 일반화 칸의 log 지연과 상관 **−0.93** (coverage는 −0.33).
  예: a+b 5-순환 768개 = 3.0회 → 지연 4,900, a+3b 1,280개 = 2.6회 → 5,800, a+b 쌍 3 1,280개 = 3.0회 → 2,100.
- 일반화 경계는 약 2.3~2.5회. 같은 관찰 수에서는 참조 그래프가 끊긴(삼각형+간선) 배선이 조금 더 어렵다(2.4회: 연결 0.65 vs 끊김 0.07).
- a+3b가 "어려운" 이유도 이것으로 설명된다: 칸이 두 배라 같은 N에서 칸당 관찰이 절반.

## E9. 합성 규칙 파일럿 (`runs_e9_small`, `runs_e9_big`, H200 ×3, 완료 10월 20일 1시 25분, 210 run)

|---|---|---|---|---|---|---|
| p_sort | 정렬 | 3 · 3 | 3 · 3 | 3 · 3 | 3 · 3 | 3 · 3 |
| p_next | 이웃 덧셈 | 3 · 3 | 3 · 3 | 3 · 3 | 3 · 3 | 3 · 3 |

- **덧셈 두 번**(comp_next_next): 16,384개까지 두 모델 모두 test 0. 출력이 세 값의 함수라 연산 표가 50 × 1,275 = 63,750칸.

| 단계 | step (예: w5_next_n3 1,280개 seed 0) | 무엇이 보이나 |

| 2. 외우기 | 200~500 | train 1.0. test에서는 **train에 나온 칸(seen)도 거의 못 맞힘**(0.05~0.2). 칸이 아니라 예제를 통째로 외운다 |

- attention 연결은 배선과 상관없이 외우기 단계에서 이미 학습된다. 지연은 연결이 아니라 연산 표를 배우는 데서 생긴다 → 배선 대칭이 지연을 정하지 않는다는 E6·E7과 맞는다.
- 실패한 run(a+3b 1,024개 seed 0 두 개)은 seen 0.10~0.14, 푸리에 0.22로 그대로. 3단계에 들어가지 못했다.

- w6_p1_n3 1,024개 seed 1은 2,000 step에서 train이 0.03으로 잠깐 무너졌다가 회복(불안정 순간).

## E19. 합성 규칙(덧셈 두 번)의 칸당 관찰 수 예측 (`runs_e19_*`, H200 ×3, 완료 10월 20일 2시 25분, 42 run, 실패 0)

`experiments/e19_comp_table.sh`. comp_next_next(x_i + 2x_{i+1} + x_{i+2})를 세 값 함수로 보고 칸당 관찰 수 = 5N / (n × n(n+1)/2).
사전 예측: 경계 약 2.3회 → n31 약 7,100개, n50 약 29,000개, 두 경계의 비율은 칸 수 비율(약 4.1배).

결과 (일반화 run / 3, 작은 모델 · 큰 모델):

| | 관찰 수 | 작은 모델 (d128·2층) | 큰 모델 (d256·4층) |
|---|---|---|---|
| n31 4,096 | 1.3 | 0 | 0 |
| n31 8,192 | 2.7 | 0 (외우기만) | **2** (지연 약 2만) |
| n31 16,384 | 5.3 | **2** (나머지 test 0.75) | 3 |
| n31 32,768 | 10.7 | 1 (나머지 0.86, 0.02 — 6만 step 안에 학습 덜 끝남) | 3 |
| n50 32,768 | 2.6 | **1** (41,200 step) | 0 (train 0.7에서 멈춤) |
| n50 65,536 | 5.1 | 2 | 0 (train 0.5 근처) |
| n50 131,072 | 10.3 | 0 (train·test 0.3·0.19, 함께 오르는 중) | 0 (train 0.2) |

- **n31: 예측과 맞음.** 1.3회는 모두 실패, 큰 모델은 2.7회(8,192개)부터, 작은 모델은 5.3회부터. 예측 경계 7,100개와 큰 모델 경계(4,096~8,192) 일치.
- **n50: 경계 근처(2.6회)에서 첫 일반화가 나왔지만 판정은 불완전.** 데이터가 3만~13만 개라 6만 step(batch 2,048) 안에 학습 자체가 끝나지 않는 run이 많다.
  특히 13만 개에서는 외우기 단계 없이 train과 test가 함께 천천히 오른다(외울 수 없을 만큼 많으면 grokking 없이 바로 규칙을 배움).
- 반대 가설(덧셈 두 번으로 나눠 배운다면 경계가 훨씬 앞) **기각**: n50 16,384개(E9)·n31 4,096개는 덧셈 칸이 충분히 관찰되는데도 실패.
  n31 경계(약 8,000)와 n50 경계(약 3만~6만)의 비율 4~8배는 칸 수 비율 4.1배와 같은 범위.
- 큰 모델은 n31에서 빠르지만 n50 큰 데이터에서는 6만 step 안에 외우지도 못함(최적화가 느림). 모델·데이터가 클 때는 step 상한을 늘려야 한다.
- 결론: **RQ2(합성 규칙)도 "실제 함수의 입력 조합 표" 기준 칸당 관찰 수로 경계가 정해진다.** 덧셈 두 번은 세 값 표(n31 15,376칸, n50 63,750칸)로 동작한다.

## E16. 고전 grokking 과제와 비교 (`runs_e16_m2`, `runs_e16_m3`, 5090, 40 run)

| m | N (칸당 관찰 수) | 일반화 · 지연 중앙값 |
|---|---|---|
| 2 | 400 (0.31) / 600 (0.47) | 0/5 / 0/5 |
| 2 | 800 (0.63) / 1,000 (0.78) | **4/5 · 22,600** / **5/5 · 2,400** |
| 3 | 425 (1.0) | 0/5 |
| 3 | 638 (1.5) / 935 (2.2) / 1,275 (3.0) | **5/5 · 6,600** / 5/5 · 1,800 / 5/5 · 300 |

- **사전 예측(우리 법칙: m=2 모두 실패, m=3은 3.0에서만) 틀림. 반대 가설(고전 grokking) 맞음.**
  m=2(두 수 → 합)는 같은 칸을 한 번도 반복해서 보지 못해도 표의 65% 이상을 보면 일반화했다(고전 연구와 같은 모습).

- 전체 로지스틱(E6~E16, E21): 관찰 수 + log 예제 수 + log m이 관찰 수만보다 훨씬 낫다(AIC 1,088 → 624). m이 길수록 어렵다.
- 해석 후보: 긴 수열은 출력마다 참조할 칸을 찾아야 하고(주의 분산), 예제 하나를 통째로 외우기 쉽다. E22(m=4·6)가 이 효과를 직접 잰다.

## E17. 무작위 연산표 (`runs_e17`, 5090, 18 run, 500 step마다 체크포인트)

| N | 무작위 표: 나온 칸 50% · 90% | 무작위 표: 안 나온 칸 (최종) | a+3b: 나온 칸 50% · 안 나온 칸 50% |

  거기서 칸 단위·연산 단위 풀이로 넘어가는 데 시간이 걸린다. (원인은 추가 분석 필요)

## E27. 정렬이 들어간 합성의 비용 (`runs_e27_*`, 5090, 완료 10월 20일 17시, 100 run, RQ2)

일반화 run / 5 (test 완전 일치 0.95 / 0.9 / 0.85 기준). 정렬이 들어간 규칙은 test 완전 일치가 0.94~0.96 근처에서 머물러 0.95 기준이 너무 빡빡하다 → 0.85·0.9 기준을 함께 본다.

| 규칙 | 768 | 1,024 | 1,280 | 1,536 | 2,048 |
|---|---|---|---|---|---|
| p_sort (정렬) | 0 / 5 / 5 | 5 / 5 / 5 | 5 | 5 | 5 |
| p_first (첫 값 더하기) | 1 / 1 / 1 | 5 · 7,100 | 5 · 1,600 | 5 | 5 |

| comp_first_sort (첫 값 더하기 → 정렬) | 0 | 0 | 0 / 0 / 2 | 0 / 0 / 5 | 2 / 5 / 5 |

- **사전 예측 맞음:** 부품 경계 약 800~1,000(정렬은 768 이하, 첫 값 더하기 약 900), 합성 경계 약 1,300~1,800(기준에 따라). 더 어려운 부품의 **약 1.5~2배.**
  대안 "합성 = 더 어려운 부품(약 1,000)"은 기각. 합성은 지연도 길다(1만 5천~5만 7천 step).
- 결론: 정렬과 덧셈을 이어 붙이면 부품 경계의 최댓값보다 1.5~2배 많은 예제가 필요하다(합성 비용).
